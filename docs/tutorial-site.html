游戏说明

在开始学习代码之前，让我们先了解 PyPacman 的游戏规则。 这是一个经典的吃豆人游戏，目标是在避免幽灵追捕的同时吃掉迷宫中的所有豆子。

基本规则

🎯 游戏目标

  • 控制吃豆人（黄色圆形）在迷宫中移动
  • 吃掉所有小豆豆（白色方块）
  • 避免被幽灵（彩色圆形）碰到
  • 吃完所有豆子即可过关

🎮 操作方式

  • 方向键 ↑↓←→：控制吃豆人移动方向
  • ESC：暂停/退出游戏
  • 吃豆人会持续移动，直到遇到墙壁或改变方向

游戏元素

计分系统

<
行为 得分 说明
吃掉小豆豆 +10 分 迷宫中有大量小豆豆，是主要得分来源
吃掉能量豆 +50 分 能量豆数量较少，但能触发幽灵恐慌
吃掉受惊幽灵+200 分 幽灵恐慌期间吃掉幽灵，高分奖励
连续吃幽灵 +400/+800 分

🔴 散开模式（Scatter）

幽灵各自回到迷宫的四个角落，在那里徘徊。 这是躲避幽灵的好时机！

持续时间：约 7 秒

🟡 追逐模式（Chase）

幽灵会主动追踪吃豆人。每只幽灵有不同的追踪策略：

  • Blinky（红色）：直接追踪吃豆人位置
  • Pinky（粉色）：预判吃豆人前方 4 格
  • Inky（青色）：复杂包抄策略
  • Clyde（橙色）：距离远时追踪，近时逃跑

持续时间：约 20 秒

🔵 恐慌模式（Frightened）

吃掉能量豆后触发，幽灵变成蓝色并随机逃跑。 此时可以吃掉幽灵获得高分！

持续时间：约 6 秒（会逐渐缩短）

游戏技巧：
  • 利用散开模式时安全地吃掉附近的豆子
  • 在追逐模式下规划好逃跑路线
  • 能量豆是翻盘的关键，在幽灵密集区使用效果最佳
  • 连续吃掉多只幽灵可以获得更高分数（200→400→800→1600）

生命与游戏结束

❤️ 生命系统

  • 初始生命：3 条
  • 被幽灵碰到：失去 1 条生命
  • 生命耗尽：游戏结束
  • 吃完所有豆子：进入下一关

🏆 高分系统

  • 游戏自动记录历史最高分
  • 最高分保存在 levels/stats.json
  • 每次游戏结束时会更新最高分
  • 挑战自己，打破记录！

五、主循环 runner.py

所有游戏都有一个「永远在转」的主循环，这是游戏编程的核心模式。

主循环流程图

src/runner.py（主循环核心代码） 
def main(self):
    clock = pygame.time.Clock()
    dt = None

    while self.game_state.running:
        # ① 处理事件
        for event in pygame.event.get():
            self.events.handle_events(event)

        # ② 清屏（涂黑）
        self.screen.fill(Colors.BLACK)

        # ③ 绘制迷宫和分数
        self.gui.draw_screens()

        # ④ 绘制精灵（吃豆人、幽灵）
        self.all_sprites.draw(self.screen)

        # ⑤ 更新精灵状态
        self.all_sprites.update(dt)

        # ⑥ 刷新显示
        pygame.display.flip()

        # ⑦ 控制帧率（60 FPS）
        dt = clock.tick(self.game_state.fps)
        dt /= 100

六、状态机 state_management.py

GameState 是整个游戏的「数据中心」，所有可变状态都集中在这里管理。

src/game/state_management.py（@property 封装） 
class GameState:
    def __init__(self):
        self.__level = 1
        self.__running = True
        self.__direction = ""
        self._points = -DOT_POINT

    @property
    def points(self):
        """读分数"""
        return self._points

    @points.setter
    def points(self, val):
        """写分数"""
        self._points = val

    @property
    def direction(self):
        return self.__direction

    @direction.setter
    def direction(self, value):
        if value not in ["r", "l", "u", "d", ""]:
            raise ValueError("Unknown direction")
        self.__direction = value
@property 的好处：外部代码可以像访问变量一样读写属性 （game_state.points = 100），但实际上会经过 getter/setter 方法。 这样可以在赋值时加入校验逻辑，防止写入非法值。

七、事件处理 event_management.py

EventHandler 负责把玩家的键盘输入转换成 GameState 的状态变化。

src/game/event_management.py 
class EventHandler:
    def handle_events(self, event):
        if event.type == QUIT:
            self.pygame_quit()

        if event.type == KEYDOWN:
            self.key_bindings(event.key)

    def key_bindings(self, key):
        if key == K_LEFT:
            self._game_screen.direction = "l"
        elif key == K_RIGHT:
            self._game_screen.direction = "r"
        elif key == K_UP:
            self._game_screen.direction = "u"
        elif key == K_DOWN:
            self._game_screen.direction = "d"

8.3 加载流程详解

关卡加载分为三个阶段：读取 JSON → 解析数据 → 初始化对象。

src/gui/pacman_grid.py - load_level() 方法 
def load_level(self, level_number):
    # 阶段 1：读取 JSON 文件
    level_path = f"levels/level{level_number}.json"
    level_json = self.get_json(level_path)  # json.load(fp)
    
    # 阶段 2：解析关键字段
    num_rows = level_json["num_rows"]           # 32
    num_cols = level_json["num_cols"]           # 35
    self.ghost_den = level_json['ghost_den']     # [14, 15]
    self._matrix = level_json["matrix"]          # 32×35 二维列表
    self._pacman_pos = level_json["pacman_start"] # [17, 16]
    self.mode_change_times = level_json['scatter_times']
    self.power_up_time = level_json['power_up_time']
    
    # 阶段 3：写入 GameState 供其他模块读取
    self._game_state.scared_time = self.power_up_time
    self._game_state.mode_change_events = self.mode_change_times
    
    # 阶段 4：计算屏幕居中偏移
    self.start_x, self.start_y = place_elements_offset(
        SCREEN_WIDTH, SCREEN_HEIGHT,
        CELL_SIZE[0] * num_cols,  # 迷宫总宽度 = 20 × 35 = 700px
        CELL_SIZE[0] * num_rows,  # 迷宫总高度 = 20 × 32 = 640px
        0.5, 0.5  # 居中锚点
    )
    
    # 阶段 5：预计算坐标矩阵（优化性能）
    self._coord_matrix = precompute_matrix_coords(
        self.start_x, self.start_y, CELL_SIZE[0], num_rows, num_cols
    )

8.4 坐标转换：逻辑格 → 屏幕像素

这是最容易混淆的部分。游戏使用两套坐标系：

逻辑坐标系（矩阵索引）

  • 原点：左上角 [0, 0]
  • 单位：格子（cell）
  • 范围：[0~31, 0~34]
  • 用途：JSON 存储、AI 寻路、碰撞检测

屏幕坐标系（像素）

  • 原点：窗口左上角 (0, 0)
  • 单位：像素（pixel）
  • 范围：[0~1023, 0~767]
  • 用途：渲染绘制、精灵位置
坐标转换公式 
# 从逻辑坐标 (row, col) 转换为屏幕像素 (x, y)
pixel_x = start_x + col * CELL_SIZE[0]
pixel_y = start_y + row * CELL_SIZE[0]

# 示例：吃豆人出生点 [17, 16]
start_x = 162  # 居中偏移（1024 - 700）/ 2
start_y = 64   # 居中偏移（768 - 640）/ 2
CELL_SIZE = 20  # 每格 20 像素

pacman_x = 162 + 16 * 20 = 482  # 屏幕 x 坐标
pacman_y = 64 + 17 * 20 = 404  # 屏幕 y 坐标

8.5 渲染管线：draw_level() 详解

渲染使用策略模式（Strategy Pattern）：通过字典 function_mapper 将单元类型映射到对应的绘制方法，避免冗长的 if-elif 链。

src/gui/pacman_grid.py - draw_level() 双重循环 
def draw_level(self):
    curr_x, curr_y = self.start_x, self.start_y
    
    # 外层循环：遍历每一行
    for row_idx, row in enumerate(self._matrix):
        # 内层循环：遍历每一列
        for col_idx, cell_type in enumerate(row):
            # 策略模式：查表获取绘制函数
            draw_func = self.function_mapper[cell_type]
            
            # 调用绘制方法，传入像素坐标和格子尺寸
            draw_func(
                x=curr_x, 
                y=curr_y, 
                w=CELL_SIZE[0],  # 20 像素
                h=CELL_SIZE[0]   # 20 像素
            )
            
            # 向右移动一格
            curr_x += CELL_SIZE[0]
        
        # 换行：x 回到行首，y 下移一格
        curr_x = self.start_x
        curr_y += CELL_SIZE[0]

8.6 策略模式的优势

使用 function_mapper 字典而非 if-elif 链的好处：

❌ 传统 if-elif 方式 
if cell == "wall":
    draw_wall(...)
elif cell == "dot":
    draw_dot(...)
elif cell == "power":
    draw_power(...)
elif cell == "void":
    draw_void(...)
elif cell == "elec":
    draw_elec(...)
# 新增类型需修改此处
✅ 策略模式（本项目采用） 
# 初始化时建表
self.function_mapper = {
    "wall": self.draw_wall,
    "dot": self.draw_dot,
    "power": self.draw_power,
    "void": self.draw_void,
    "elec": self.draw_elec,
}

# 使用时一行搞定
draw_func = self.function_mapper[cell]
draw_func(...)
扩展性：如果要新增一种单元类型（比如 "teleport" 传送门）， 只需：① 在 JSON 中使用 "teleport"；② 实现 draw_teleport() 方法； ③ 在 function_mapper 中添加映射。无需修改 draw_level() 循环逻辑。

8.7 完整数据流总结

性能优化：draw_level() 每帧都被调用（60fps），但由于使用预计算的 _coord_matrix 和策略模式查表，实际开销很小。32×35=1120 次循环在现代 CPU 上几乎无感。 如果需要进一步优化，可以考虑只重绘变化的格子（脏矩形算法），但本项目未采用。

十、幽灵 AI ghosts.py

四只幽灵各自有不同的追逐策略，这是经典吃豆人游戏的核心玩法。

多态示意图

核心架构：策略模式 + 抽象基类

所有幽灵都继承自 Ghost 基类，它使用了 ABC（抽象基类）和 @abstractmethod 装饰器，强制每只幽灵实现自己的追逐策略。

src/sprites/ghosts.py（抽象基类定义） 
from abc import abstractmethod, ABC

class Ghost(Sprite, ABC):
    """幽灵基类：图像、lerp 行走、scared 状态、碰撞"""
    
    @abstractmethod
    def determine_target(self):
        """子类必须实现这个方法，返回追逐目标格子 (row, col)"""
        pass
Python 知识点：ABC（Abstract Base Class）+ @abstractmethod 是 Python 实现接口的方式。 它确保子类必须实现特定方法，否则无法实例化该子类。这是设计模式中的"模板方法模式"。

Blinky（红色）：直接追踪

最简单粗暴的策略：直接追吃豆人当前位置。Blinky 是玩家的"影子"，始终紧追不舍。

src/sprites/ghosts.py - Blinky 实现 
class Blinky(Ghost):
    """红色 Blinky：最直接追逐"""
    
    def determine_target(self):
        mode = self._game_state.ghost_mode
        
        if mode == "scatter":
            # 散开模式：回到右上角 (0, 30)
            return GHOST_SCATTER_TARGETS[self.name]
        
        elif mode == "chase":
            # 追逐模式：直接追吃豆人脚下的格子
            pacman_rect = self._game_state.pacman_rect
            # 把像素坐标转换成网格坐标 (row, col)
            target = self._get_idx_from_coords(
                (pacman_rect[0], pacman_rect[1])
            )
            return target

关键方法：_get_idx_from_coords() 把吃豆人的像素坐标转换成网格坐标。

Pinky（粉色）：预判前方 4 格

伏击型策略：瞄准吃豆人前进方向的前方 4 格。当玩家直线逃跑时，Pinky 会"抄近路"到前方拦截！

src/sprites/ghosts.py - Pinky 实现 
class Pinky(Ghost):
    """粉色 Pinky：伏击型追逐"""
    
    def determine_target(self):
        mode = self._game_state.ghost_mode
        
        if mode == "scatter":
            # 散开模式：回到左上角 (0, 0)
            return GHOST_SCATTER_TARGETS[self.name]
        
        elif mode == "chase":
            # 追逐模式：瞄吃豆人面前 4 格
            return self.calculate_pacman_direction()
    
    def calculate_pacman_direction(self):
        # 读取吃豆人当前方向：'l'/'r'/'u'/'d'
        pacman_dir = self._game_state.pacman_direction
        pacman_rect = self._game_state.pacman_rect
        
        # 像素坐标转网格坐标
        pacman_rect = self._get_idx_from_coords(
            (pacman_rect[0], pacman_rect[1])
        )
        
        # 关键：调用 get_target_pacman_dir，默认 look_ahead=4
        return self.get_target_pacman_dir(
            pacman_rect, pacman_dir
        )

核心方法 get_target_pacman_dir()：根据吃豆人方向计算前方 N 格的目标位置。

src/sprites/ghosts.py - 前方目标计算 
def get_target_pacman_dir(self, pacman_rect, pacman_dir, look_ahead=4):
    """计算吃豆人前方 look_ahead 格的目标"""
    
    if pacman_dir == "l":  # 向左
        target = (pacman_rect[0], pacman_rect[1] - look_ahead)
        # 处理隧道穿越
        if target[1] < 0:
            target = (pacman_rect[0], self.num_cols - look_ahead - 1)
        return target
    
    elif pacman_dir == "r":  # 向右
        target = (pacman_rect[0], pacman_rect[1] + look_ahead)
        if target[1] > self.num_cols:
            target = (pacman_rect[0], 0)
        return target
    
    elif pacman_dir == "u":  # 向上
        return (pacman_rect[0] - look_ahead, pacman_rect[1])
    
    elif pacman_dir == "d":  # 向下
        return (pacman_rect[0] + look_ahead, pacman_rect[1])
    
    else:
        return pacman_rect  # 没有方向时，目标就是脚下

Inky（青色）：向量镜像包抄

最复杂的策略：基于 Blinky 和吃豆人位置计算镜像点。Inky 的路径最"飘"，会根据 Blinky 和吃豆人的相对位置形成包抄！

src/sprites/ghosts.py - Inky 实现 
class Inky(Ghost):
    """青色 Inky：向量镜像追逐（最复杂）"""
    
    def calculate_inky_target(self):
        pacman_rect = self._game_state.pacman_rect
        pacman_rect = self._get_idx_from_coords(
            (pacman_rect[0], pacman_rect[1])
        )
        pacman_dir = self._game_state.pacman_direction
        
        # 关键：必须读取 Blinky 的当前位置（每帧更新）
        blinky_cell = self._game_state.blinky_matrix_pos
        
        # 步骤 1：吃豆人前方 2 格
        inky_pacman_target = self.get_target_pacman_dir(
            pacman_rect, pacman_dir, look_ahead=2
        )
        
        # 步骤 2：计算向量 Blinky → 伪目标点
        vec_row = inky_pacman_target[0] - blinky_cell[0]
        vec_col = inky_pacman_target[1] - blinky_cell[1]
        
        # 步骤 3：向量加倍，得到最终目标
        target_row = blinky_cell[0] + vec_row * 2
        target_col = blinky_cell[1] + vec_col * 2
        
        return target_row, target_col
    
    def determine_target(self):
        mode = self._game_state.ghost_mode
        if mode == "scatter":
            return GHOST_SCATTER_TARGETS[self.name]  # 左下角
        elif mode == "chase":
            return self.calculate_inky_target()
数学原理：
  1. 先找到吃豆人前方 2 格的点 P
  2. 计算从 Blinky 到 P 的向量 V = P - Blinky
  3. 目标 = Blinky + V × 2

依赖关系：Blinky 必须在每帧更新 game_state.blinky_matrix_pos， 否则 Inky 的锚点就过时了。

Clyde（橙色）：距离切换策略

胆小鬼策略：远时随机乱走，近时突然追击。Clyde 远看像在闲逛，一旦靠近就突然变得激进，与 Blinky 的持续压迫形成互补！

src/sprites/ghosts.py - Clyde 实现 
class Clyde(Ghost):
    """橙色 Clyde：距离切换「随机 / 追逐」"""
    
    def get_clyde_random_target(self):
        pacman_rect = self._game_state.pacman_rect
        pacman_rect = self._get_idx_from_coords(
            (pacman_rect[0], pacman_rect[1])
        )
        
        # 第一帧还没有当前位置
        if not self.curr_pos:
            return pacman_rect
        
        # 计算曼哈顿距离：|dr| + |dc|
        dis = abs(pacman_rect[0] - self.curr_pos[0]) + \
              abs(pacman_rect[1] - self.curr_pos[1])
        
        # 距离 > 8 格：假装随机
        if dis > 8:
            return self.get_random_target()
        # 距离 ≤ 8 格：真正追击吃豆人
        return pacman_rect
    
    def get_random_target(self):
        # 在整个地图范围内随机选一个格子
        rand_row = random.randrange(0, self.num_rows)
        rand_col = random.randrange(0, self.num_cols)
        return rand_row, rand_col
    
    def determine_target(self):
        mode = self._game_state.ghost_mode
        if mode == "scatter":
            return GHOST_SCATTER_TARGETS[self.name]  # 右下角
        elif mode == "chase":
            return self.get_clyde_random_target()

移动执行：贪心算法

所有幽灵确定目标后，移动逻辑是统一的：在每个岔路口选择最接近目标的方向（贪心一步）。

src/utils/ghost_movement_utils.py 
def get_direction(curr_pos, target_pos, valid_directions):
    """在岔路口选择最接近目标的方向（贪心一步）"""
    best_dir = None
    best_dist = float('inf')
    
    for direction in valid_directions:
        next_pos = (curr_pos[0] + direction[0], 
                    curr_pos[1] + direction[1])
        # 欧氏距离的平方（避免开方，性能更好）
        dist = (next_pos[0] - target_pos[0])**2 + \
               (next_pos[1] - target_pos[1])**2
        if dist < best_dist:
            best_dist = dist
            best_dir = direction
    
    return best_dir
为什么不用 A* 寻路？
四鬼采用岔路口贪心策略，计算轻量，行为接近街机原版。A* 寻路虽然能找到最优路径， 但计算量大，而且会让幽灵变得"太聪明"，失去经典吃豆人的游戏感觉。

状态机：三种模式切换

幽灵行为由 GameState.ghost_mode 控制，在三种模式间切换：

🔴 Scatter（散开）

各自回到地图四角的固定位置徘徊。这是躲避幽灵的好时机！

持续时间：约 7 秒

🟡 Chase（追逐）

使用上述 AI 策略主动追踪吃豆人。每只幽灵有自己的目标计算方法。

持续时间：约 20 秒

🔵 Frightened（恐慌）

吃能量豆后触发，幽灵变蓝并随机逃跑，此时可以被吃掉！

持续时间：约 6 秒（会逐渐缩短）

模式切换由定时器事件驱动 
# src/runner.py
def create_ghost_mode_event(self):
    CUSTOM_EVENT = pygame.USEREVENT + 1
    # 从 JSON 读取 scatter/chase 切换时间
    pygame.time.set_timer(
        CUSTOM_EVENT,
        self.game_state.mode_change_events * 1000
    )

总结：四鬼策略对比

幽灵 策略 核心算法 游戏特点
Blinky 直追 target = pacman_pos 持续压迫，玩家的"影子"
Pinky 埋伏 target = pacman_ahead(4) 抄近路拦截，预判玩家动向
Inky 包抄 target = blinky + vec×2 路径最飘忽，依赖 Blinky 位置
Clyde 胆小 if dist>8: random else: chase 远时闲逛，近时激进
设计精妙之处：
  • 使用 ABC + @abstractmethod 强制每只幽灵实现自己的策略
  • 通过 GameState 共享数据（如 Blinky 位置供 Inky 使用）
  • 所有幽灵共用移动逻辑（贪心算法），只有目标计算不同
  • 状态机控制模式切换，增加游戏节奏变化

这就是为什么吃豆人游戏即使简单，玩起来却很有挑战性——四只幽灵的不同策略形成了复杂的协作追击！

十一、音效系统 sounds.py

SoundManager 使用单例模式，确保全局只有一个音效管理器实例。

src/sounds.py（单例模式） 
class SoundManager:
    _instance = None

    def __new__(cls, *args, **kwargs):
        if not cls._instance:
            cls._instance = super().__new__(cls, *args, **kwargs)
        return cls._instance

    def __init__(self):
        if not hasattr(self, "_initialized"):
            self._initialized = True
            self._sounds = {}
            pygame.mixer.pre_init()

    def play_sound(self, name):
        if name in self._sounds:
            self._channels[name].play(self._sounds[name]['sound'])
单例模式的作用：在 runner.py 里创建一次 SoundManager() 并加载音效后， 在其他模块里再次 SoundManager() 会得到同一个对象，可以直接播放已加载的音效。
